# Native decoder paired profile

This profile compares the preserved pre-native-decoder release package with the current native-decoder release using the existing `benchmarks/profile.py` runner. The paired `baseline/` and `candidate/` directories contain the runner's raw nine-process samples, per-case medians and median absolute deviations (MAD), fingerprints, environment/build provenance, and charts. Both runs used 100 warmup calls, 500 base rounds, and nine independent processes; workload-specific iteration counts are recorded in each case.

The baseline is the isolated preserved release package at `/tmp/native-decoder-baseline/site`, whose loaded extension SHA-256 is `36502b893f69ae0c7bf8b159d53099b17c7ec02446c14b5d6a3555a6a278d581`. It includes FEAT_004's direct encoder and vendored decoder. The candidate extension and Cargo release artifact match at SHA-256 `ca06f077c3ca1f2a72270b06d5799bc851a7612dec4728e6407839fe95aa1a94`. Both use Python 3.14.7, rustc 1.98.1, and Cargo 1.98.1 on the same host.

All 24 workloads had matching input and wire SHA-256 fingerprints. Decode median latency fell for all 24 cases. The three 10,000-entry map profiles improved by 5.29–5.41x (9.13–9.32 ms to 1.72–1.73 ms); the three 1,000-entry maps improved by 3.98–4.09x (610–618 us to 151–153 us). Other decode cases improved by 1.09–3.66x. This supersedes the [BUG_005 historical investigation](../../project-notes/reviews/mixed_profile_decode_history.md) for the current decoder; it does not establish that the old decoder alone caused the historical slowdown.

Encode is included as a control. Most encode medians were broadly similar or improved, while `integer_width_boundaries` regressed from 23.5 us to 28.6 us (about 1.22x slower). An interleaved retest confirmed that control shift; see [BUG_007](../../project-notes/requirements/BUG_007_integer_encode_regression.md) and the raw [paired samples](interleaved_integer.json). Inspect the per-process samples and MADs in the JSON before interpreting small differences. These timings do not measure cache misses, allocation counts, or explain causality. The baseline was captured from a preserved package and the candidate from the current worktree, so this main profile is a paired workload and environment comparison rather than an interleaved run.

## Interleaved integer encode follow-up

The integer encode shift persisted in a focused interleaved run using nine adjacent fresh-process baseline/candidate pairs, alternating which role ran first. Each process warmed and timed the same 2,435-byte `integer_width_boundaries` payload with 100 warmup and 500 timed `dumps()` calls. The baseline median was 23.389 us (MAD 0.258 us); the candidate median was 28.414 us (MAD 0.216 us), a 1.215x ratio. The shift exceeds both MADs; this confirms the measured regression without identifying its cause. Input SHA-256 is `149c605090eae16a67e5354524d0abfb43c24ef2cb052e2f7f61d2e849395d08`, and wire SHA-256 is `6471484050db5344b0710f65f4abfa2b5d5779ce201b69edfe9fbd2f6d99af8b` in both roles. Raw process samples, pair order/PIDs, and binary hashes are in [`interleaved_integer.json`](interleaved_integer.json); [`interleaved_integer.py`](interleaved_integer.py) reproduces the capture.
